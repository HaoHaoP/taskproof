# 派活的省钱纪律

这是 [`../SKILL.md`](../SKILL.md) 铁律 7–11 的细则。写卡前读一遍。整份文件只为一件事：主智能体的上下文该花在**判断**上，而不是重做机器已经做过的事、或复述操作者已经写过的东西。

## 1. 复核：什么算「已经证明过」

发车流程自己的第 ⑦ 步会用卡的工作目录跑一次道里的 `verify` 命令，把结果落进账本（`verify_cmd`、`verify_exit`、`verify_summary`，以及事件流）。那是**关于代码的机器结论** —— 不是自述，也不需要你复现一遍。所以按「谁能回答」分工：

| 问题 | 谁来回答 | 你做什么 |
|---|---|---|
| 注册的那条命令现在还过吗？ | 机器，第 ⑦ 步 | 读 `taskproof show <id>` |
| 那条命令到底跑没跑？ | 机器 | `verify_cmd == SKIPPED` → 见例外 1 |
| 命令覆盖得了卡里的要求吗？ | 你 | 写卡那一刻决定，见 1.2 |
| worker 有没有越出这张卡？ | 你 | 读 diff |
| 在真实运行态里对吗？ | 你 | 一条命令、一个数：重跑卡里那条 `check-*.mjs` / 量一个值 / 比一次字节 |
| 删改类：该留的还在不在？ | 你 | 改前改后各清点一次 |
| 这就是操作者要的吗？ | 操作者 | 问一次，附推荐 |

**那一行有上限，不是「可以随便探索」的许可。** 分两档：

- **收口档（你自己做）**：重跑卡里那条脚本、打开页面量一个数值、比一次字节/指纹 —— 上限就是
  「一条命令、一个数」，做完就报。
- **探索档（先折进卡，别在会话里现搭）**：找根因、连内网后端、抓 XHR、连点翻页这类，第一件事是把探针
  **固化成项目里的 `check-*.mjs` 写进卡**（worker 先红后绿，你只重跑那一条），或先写成「待验证清单」
  进该项目的进度文件再决定派什么卡。真需要登录态的，优先用操作者给的测试 token 让 worker 跑脚本。
- **停手闸门**：同一件事上工具调用超过 ~10 次、或超过 ~15 分钟还没结论 → 停手：写卡、写待办、
  或找操作者（同第 4 节「不要和自己成环」）。

读账本之前先记住两条：

- **SKIPPED 不是通过。** 道里没有 `verify`，或发车时带了 `--no-verify`，账本记 `SKIPPED` —— 而这张卡照样落 `done`，因为没有任何东西失败。这一种只有你能发现。
- **`blocked` 与 `failed` 是两种判决。** `blocked`（越界）意味着第 ⑦ 步**根本没跑**；`failed` 才是验收真跑了且红了。

只有这三种情况才重跑 `taskproof verify <id>`：

1. **SKIPPED** —— 什么都没被验过，你就是唯一的检查。
2. **覆盖面不够** —— 卡里要求的东西命令看不见：一个渲染出来的数值、一个必须**不**存在的文件、404 路径上的退出码、删掉的东西真的还删着。这类断言你自己补，一条命令、一个数。
3. **假绿嫌疑** —— 结构上就不可能红的检查。本项目已实测到的品种：`npx eslint <view>` 打在 `.eslintignore` 覆盖的路径上（输出「File ignored because of a matching ignore pattern」并 exit 0）；只断言源码文本的测试（`toContain('@command="fn(key)"')` 那种原理上看不见编译期问题）；`npm run build` 绿了但产物其实是空的。每一种都已经真的废掉过一张卡。

**红**是镜像的那一类，默认值得多看一眼：在同一棵树里连跑 2~3 次再定性 —— 机器上同时跑着几条道时，带轮询/等待的测试会假红，本项目已经为一次假红付过一整轮返工。真红就在树里修，别把整张卡重发一遍。

### 1.2 把验收命令写成真能红的那种

复核想省钱，前提是那条命令扛得住。所以：

- 一条命令一个判决：`exit 0` 等于卡里的要求都满足了；
- 一张卡只闭一个根因时，命令点名具体的测试/目标（见第 3 节），别一上来就跑全宇宙；
- 与注册表里的 `verify` 保持逐字一致 —— 卡里的验收命令和它不一样本身就是缺陷；
- 发车前在干净树上手跑一次，必须是**绿**的：干净树上就红的命令会让这条道每张卡都失败，而发车前就绿的命令从来也没在检查这张卡。

## 2. 素材：给路径，不复述

卡正文**就是** worker 收到的 prompt —— 整份卡作为一个 argv 传进去。所以凡是指得出来的，就指过去：

````
## 素材（自己读，不要我复述）
- 原型：/absolute/path/to/prototype/viewer.html:1710-1735
- 设计口径：/absolute/path/to/design/taskgroup.md 第 3 节
- 上次的真实输出：/absolute/path/to/logs/board.html
````

规矩：

- 绝对路径**加行号范围**；只存在于你脑子里的那个路径就是复述；
- 明写一句：*自己读，不要我复述*；
- worker 读得到仓外的东西：codex 适配器走 `-C <workdir> --sandbox workspace-write`，限的是**写**，不是读；
- 素材是 worker 看不见的图时，只描述由像素决定的部分（尺寸、颜色、间距），并给出它必须对齐的那个组件的 `file:line`；
- **不要**为了「稳妥」再用自己的话把设计讲一遍。精度就死在那里，而且花两次钱：压缩一次，修误读又一次；
- 素材放在稳定的地方 —— 项目自己的 `docs/` 或 `prototypes/`，别放 `/tmp`（别的任务有权清它）。

## 3. 卡里的 TDD

按「这活改不改行为」分两种形状。

**改行为 / 修 bug → 测试点名写在卡里。** 验收命令给每个根因点名一条测试：

```bash
cd /absolute/path/to/repo && python -m unittest tests.test_cli.TestDispatch.test_refuses_full_cap -v && python -m unittest discover -s tests
```

为什么是这个形状：taskproof 只看退出码，所以「这条测试必须先失败」本身没法当验收（硬写成 `! cmd` 就成了一道谜语，worker 会解错）。点名测试让它的**存在性**由机器判定 —— 没写的测试是红，不是静默通过 —— 而测试名告诉了操作者这张卡闭的是哪个根因。worker 的交付里再贴一次**修之前跑出来的失败输出**；你核对的是「红真的存在过」，不是自己重新推一遍。

**不改行为 → 单开一张只写测试的卡。** 给已有代码补测试、或重构前先铺网，都是一张独立的卡：验收是新测试绿 + 全量回归绿，硬约束是「不许改任何生产文件」—— 写进卡里，并在道允许时用 `forbidden_paths` 兜住。卡里点名 `tdd` skill 的路径（`~/.codex/skills/tdd/SKILL.md`），免得 worker 去猜你说的 TDD 是什么。

但**不要**把每张卡都拆成「先写测试的卡 + 再改码的卡」：那是为一个根因付两次派发、两次复核、两个提交边界。只有测试这活自己站得住时才拆。

## 4. 闭环返工、待办、人工闸门

这一节要拦的失控长相是：主智能体做完一张卡，又看出三件事，于是又派三张卡 —— 每张都要花上下文、复核时间与一个提交边界，而这三张卡没人要过。给它边界的那条规矩是：**一张卡要么是闭环返工，要么是操作者的决定。**

- **闭环返工 —— 免费一次。** 验收红了，或者 diff 并没有真把根因闭掉。先自己诊断：可能是卡写错了，不一定是 worker 的错。同一个根因再发一张卡不需要任何人点头。若它第二次以同样的方式红，停下来把问题交给操作者，不要发第三张。
- **待办 —— 其余一切。** 第二个 bug、别处的异味、缺的测试、更漂亮的改法、你顺手撞见的不一致：往该项目卡目录旁边的 `backlog.md` 写一行 —— `做什么 · 在哪 (file:line) · 为什么不属于这张卡`。不发卡、不发车。整份文件一次性交给操作者，逐行附上你的推荐。
- **人工闸门。** 凡不是闭环返工的卡，都要操作者明确点头。问的时候一次一题、每题带推荐 —— 一次抛多题的表单往往会没人答。
- **能给人看的一律先给人看。** 这些本来就不该成卡：观感（「看着对吗」）、产品取舍、数据口径问题、「这是我要的吗」。把服务起起来，给 URL 加一句「看哪里」，让答案决定要不要有这张卡。一条消息的成本，省掉一整个派发来回。
- **不要和自己成环。** 「验证 → 觉得有问题 → 派卡」在同一件事上重复超过一次，是失控，不是尽责。第二次发生时，写下来，去找操作者。

## 5. 模型降级

两级，逐卡决定。

**一级 —— `--reasoning none`，以及配了便宜模型时的 `--model <cheap>`。** 判据是这张卡**可枚举、机器可判**：

- 文档对镜（中文那份与英文那份必须说同一件事）
- 一次性改名、路径替换、引用清扫
- 机械重排格式、生成清单、计数
- 照抄一个已存在输出的形状（一行表格、一个 JSON 字段、一个配置块）

两个问题决定要不要降：**不重读一遍代码，你能写出验收命令吗？** 以及 **worker 失败时，光看 diff 能定性吗？** 两个都是 → 降。任何需要跨文件判断的（架构、闸门语义、UI 几何）都留在正常模型上。

**二级 —— 本地模型**，用 `custom:<cmd>` 指向本地服务，或在 codex 配置里挂一个本地 provider。适用面是一级的子集，另外加三条：

- **独占一个 `group`** —— 本地服务本来就是串行的，独占锁把这件事写明白，而不是让它表现为「这条道莫名很慢」；
- 绝不放进并行波次：一条道、同一时刻一张卡，别的道闲着；
- 先拿一张「文档对镜」类的小卡试水，读完它的 diff 再让这条道接别的东西。

本机现状：`--reasoning none` 现在就能用。本地**聊天**模型还没就绪 —— LM Studio 的 `http://127.0.0.1:1234/v1/models` 只挂了一个 `text-embedding-nomic-embed-text-v1.5`。等模型就绪，先接上道，再跑那张试水卡。

## 6. 写卡怎么省

- 用 `../templates/card.md` / `../templates/card.zh-CN.md` 填，别自由发挥写长篇简报。一张需要三段背景才说得清的卡，是还没想清要什么。
- 一个根因、一段文件范围、一条验收命令、一个提交边界。
- 不写 worker 没法据以行动的散文：没有「请小心」、没有排查过程的历史、没有对话内容摘要。
- 只写你真会去查的硬约束；每一条都在花 worker 一次阅读，其余是邀请它到处乱逛的噪音。
- 卡文件放在项目的卡目录目录里，让卡里的路径与 worker 的工作目录说的是同一棵树。
